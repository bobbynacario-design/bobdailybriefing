# App audit — 9 September 2026

## Assessment and scope

The app has substantial capability, but the next investment should be reliability, trustworthy presentation, and a simpler daily workflow. Its strengths are cross-feed triage, source-linked evidence, decision reviews, explicit feed health, and shared, tested scoring modules.

Reviewed repository code, deployment/CI configuration, and the signed-in deployed app in the Codex browser. Visually inspected Today and Command at approximately 782px viewport width; exercised Command navigation, Refresh, reload, and Search. All existing `npm test` suites and application smoke checks passed. Mobile, all other tabs, notification delivery, production backend permissions, and concurrent writes were not exercised. This is not a full penetration test or factual verification of the briefing's news. No fixes or deployments were made. Existing workspace changes were preserved.

Search accepted “insurance” but retained its initial prompt. Show a recoverable dependency/load error instead of an inert screen. | P1 | **Unknown source verification is invisible.** The loaded briefing had `grounding:null`, and its story records had empty URLs and `grounded:false`. | P1 | **Generation authorization and cost controls need strengthening.** The briefing callable checks authentication, accepts a caller-selected model, and has no visible per-user generation quota (`functions/index.js:253–269`). Research reads a counter before launching paid work and writes `count + 1` afterward (`440`, `514`), so concurrent requests can pass the same limit. | Enforce the intended owner/role policy server-side, allowlist models, add transactional quota reservation and idempotency before provider calls, and reconcile failed jobs. | P1 | **Private local cache is not account-scoped.** `briefings_bob_cache` is shared across accounts and survives `lockSession` (`index.html:2617`, `2706`). | Scope caches to UID; clear private memory and rendered views on sign-out; define whether offline storage is retained. ## UI improvements

1. **Simplify navigation.** Fourteen equal-weight destinations wrap into several rows at the inspected width. Use five primary destinations: Home, Explore, Research, Decisions, and More. Group Radar/PSE/Markets/Sports under Explore and Evidence/Timeline/History under research/archive navigation. Keep Search globally available. On mobile, use four frequent destinations plus More instead of a long horizontal strip.
2. **Make Home the daily workflow.** Combine Today's overview with a working Morning 5: what changed, why it matters, the source, and the next review. Put full briefing reading below that. Avoid two competing priority lists.
3. **Separate metric values from narrative.** The USD/PHP value includes a long date/source explanation in large type, making the entire ticker exceptionally tall. Normalize value, unit, change, as-of date, and source into separate fields. Put weather detail and market commentary behind expansion.
4. **Move authoring below reading.** Hide the raw JSON editor, prompt-copy instructions, and schema diagnostics inside an Import/Advanced panel. Keep Generate available with clear running, failed, and completed states. Place Copy/PDF next to the content they export rather than as apparently global actions.
5. **Improve reading hierarchy.** Preserve the restrained dark/gold identity. Use larger body text, clearer secondary text, shorter summaries, and fewer uppercase micro-labels. Keep source status and publication time visible while expanding explanation on demand. Verify contrast numerically rather than assuming the theme passes.
6. **Use one card interaction pattern.** Consistent actions: Open source, Save evidence, Create decision, Follow, Reviewed. `commandGo` currently opens only the source tab (`index.html:4668`); it should open and highlight the exact item, with a route back to the originating queue.

## Functional enhancements worth building next

- **Changes since last visit:** group recurring stories by event, mark new versus updated, and summarize meaningful changes without duplicating the same oil/FX story across sections.
- **Complete the evidence-to-decision path:** prefill a decision from an evidence item; retain the captured source version, thesis, invalidation condition, review date, and outcome. Surface due reviews on Home.
- **Unified follows:** let users follow entities/topics across briefing, news, markets, and sports with explicit alert thresholds and quiet periods. Preserve reliability warnings.
- **Evidence export:** produce a dated research pack containing selected items, source URLs, capture/publication dates, verification status, and personal notes.
- **Operational visibility:** show last successful data refresh separately from last attempt and page render time. Expose partial failures and recovery actions in plain language.

## Engineering and delivery plan

The 9,560-line `index.html` combines Firebase access, styling, routing, and nearly all feature rendering. Gradually extract data services, routing, shared UI primitives, and feature modules; a framework rewrite is not required. Keep the existing pure scoring cores.

The current smoke script mainly checks strings, IDs, and parsing. Add a small browser suite covering sign-in state, Command population, Search-to-source navigation, evidence round-trip, keyboard operation, responsive layout, and offline/account transitions. Gate static publishing on successful checks; the publishing workflow currently runs independently of CI. Include a deployment version identifier and test updates with the service worker active.

Recommended sequence:

1. Diagnose live Command/Search failures; fix unknown verification state, quota concurrency, and private cache boundaries.
2. Simplify navigation/Home; normalize ticker fields; correct priority ordering; implement exact-item navigation and accessibility fixes.
3. Improve cross-device evidence persistence, search coverage/retry, and decision handoffs.
4. Add change tracking, follows, and evidence export after the core workflow is dependable.
